Update mode

Default is Dynamic — agent updates itself automatically.

Find versions: apt-cache madison instana-agent-dynamic
F

Version pinning & update schedule

Control when and to which version the agent auto-updates. Useful for reproducing customer issues with an exact sensor build, or for change-freeze windows.

Written to AgentBootstrap.cfg as version = <tag> — freezes all sensor downloads at that release. Find release tags at github.com/instana/agent-updates/tags. Leave empty for automatic updates.
Jitter of ±30 min is applied automatically to spread load across agents.
E

Resources (memory & CPU)

Default memory is 512–544 MB. Increase only when the agent log shows OutOfMemoryError or when monitoring many entities (IBM MQ, OMEGAMON, cloud sensors).

Set as systemd drop-in Environment=AGENT_MAX_MEM=1024M. Default: 544 MiB. Restart agent after change.
Optional. Set as systemd drop-in Environment="JAVA_OPTS=..." (e.g. -Xmx1g).
Passed as --memory=1g to docker run. Use m for MB, g for GB.
Passed as --cpus=0.5. IBM docs advise using soft limits — hard CPU limits can cause throttling.
Set request = limit for Guaranteed QoS (prevents eviction).
IBM docs: CPU limits not recommended — causes throttling. Use only if required by cluster policy.
