App Servers & Web

MySQL — auto-discovered on localhost:3306

MySQL Setup SQL (Documented Permissions):CREATE USER 'instana'@'localhost' IDENTIFIED BY '<password>'; GRANT SELECT, PROCESS, REPLICATION CLIENT ON *.* TO 'instana'@'localhost'; FLUSH PRIVILEGES;

MariaDB — separate sensor, MySQL sensor does not monitor MariaDB

MariaDB Setup SQL (Documented Permissions):CREATE USER 'instana'@'localhost' IDENTIFIED BY '<password>'; GRANT SELECT ON performance_schema.* TO 'instana'@'localhost'; GRANT SLAVE MONITOR ON *.* TO 'instana'@'localhost'; FLUSH PRIVILEGES;

PostgreSQL — auto-discovered on localhost:5432

Optional. Used for authentication only.
PostgreSQL Setup SQL (Documented Permissions):CREATE USER instana WITH PASSWORD '<password>'; CREATE DATABASE instana OWNER instana; GRANT CONNECT ON DATABASE instana TO instana; GRANT pg_monitor TO instana; -- PostgreSQL 10+

MongoDB — auto-discovered on localhost:27017

Database where user is defined (source)
MongoDB mongosh Command (Documented Permissions):use admin db.createUser({ user: "instana", pwd: "<password>", roles: [ { role: "read", db: "admin" }, { role: "clusterMonitor", db: "admin" }, { role: "read", db: "local" } ] })

Redis — auto-discovered on localhost:6379

Leave empty if Redis has no authentication
Redis Setup Note:# In redis.conf (if password protected): requirepass "<password>" # CONFIG command must be accessible to the agent. # If CONFIG was renamed with rename-command, specify config-command in configuration.yaml.

Microsoft SQL Server

Linux: DEFAULT (confirmed on a live agent). Windows: MSSQLSERVER or the named instance. A wrong name removes the sensor ("invalid or missing configuration").
SQL Server Setup SQL (Documented Permissions):CREATE LOGIN instana WITH PASSWORD = '<password>'; CREATE USER instana FOR LOGIN instana; GRANT VIEW SERVER STATE TO instana; GRANT VIEW DATABASE STATE TO instana; -- For disk volume & auto-growth metrics, add sysadmin membership or db_owner.
